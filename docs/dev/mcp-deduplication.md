# MCP: без дублей (глобально / плагин / проект)

**Не часть продуктовой спеки** (`docs/spec/`): только для IDE-агентов. Запуск приложения — [`docs/spec/RUNBOOK.md`](../spec/RUNBOOK.md).

- Last updated: 2026-04-19

## Проблема

Один и тот же инструмент может подключиться **дважды**: например **Playwright** и как MCP в **локальном** конфиге проекта (`~/.claude.json` по пути репо), и как **встроенный** сервер плагина **everything-claude-code** (`plugin:everything-claude-code:playwright`). В UI оба «connected», контекст и лимиты расходуются впустую.

## Правило приоритета (для агентов)

1. **Уже есть глобально** (User MCPs, Built-in / plugin) — **оставляем это** и **не** добавляем второй экземпляр с тем же назначением из профиля проекта.
2. **Нет** нужного сервера глобально — тогда можно подтянуть из проекта: `node scripts/mcp/install-user.mjs --profile standalone`.
3. **Конфликт уже создан** (как на скриншоте: локальный `playwright` + plugin playwright) — **убрать дубль на стороне проекта**: удалить запись **локального** MCP для этого репозитория в `~/.claude.json` (секция по пути проекта), оставить **plugin / global**. Агент **не** должен снова записывать в project-local те серверы, которые уже покрывает плагин.

## Что перекрывает everything-claude-code (типично)

Сверяйте с вашей версией плагина; обычно дублируются по смыслу:

| Назначение            | Пример имён в UI                          |
|-----------------------|--------------------------------------------|
| Документация          | `plugin:...:context7`                      |
| GitHub                | `plugin:...:github`                        |
| Playwright / браузер  | `plugin:...:playwright`                    |
| Memory                | `plugin:...:memory`                        |
| Sequential thinking   | `plugin:...:sequential-thinking`           |
| Поиск (Exa)           | `plugin:...:exa`                           |

Локальный MCP с **коротким** именем (`playwright`, `context7`, …) в конфиге **проекта** при включённом плагине — лишний.

## Профили в этом репозитории

| Файл | Когда использовать |
|------|---------------------|
| `mcp/car-service-platform.default.json` | **Пустой** `mcpServers` — по умолчанию. `install-user` только мержит **существующее** + опциональный `local.overrides.json`. **Не** плодит дубли к ECC. |
| `mcp/car-service-platform.standalone.json` | Полный набор stdio-серверов — если **нет** ECC / плагина и нужно поднять context7, playwright, … одной командой: `--profile standalone`. |

## Verify и пустой `mcpServers` (Cursor / Claude Code)

После merge с **пустым** профилем в `~/.cursor/mcp.json` или `~/.claude/settings.json` объект `mcpServers` может быть `{}` — это **нормально**, если инструменты приходят только из плагина ECC / Built-in. Скрипт `scripts/agents/verify-agent-environment.mjs` при пустом списке пишет **предупреждение** (проверка всё равно проходит). Чтобы считать пустой список ошибкой, передайте **`--strict`**.

## GitHub и плагин

Если нужен GitHub из **плагина** ECC (`plugin:...:github`), настройте токен по документации плагина (env / UI). Для **stdio**-сервера с именем `github` можно положить секреты в **`mcp/local.overrides.json`** (шаблон — `local.overrides.json.example`); в репозиторий не коммитить. **Не** добавляйте второй экземпляр `github` (plugin + stdio) без необходимости — см. правило приоритета выше.

## Предупреждение пользователю (лишние MCP)

Подключённые **глобально** MCP всё равно попадают в сессию (описания инструментов расходуют контекст), даже если агент их не вызывает.

**Агент обязан** (обычно **один раз за сессию** — после `verify` / bootstrap или в первом содержательном ответе) вывести пользователю короткий блок **MCP hygiene**, если из контекста видно много серверов или это первая настройка:

- Рекомендация **отключить в настройках клиента** MCP, которые **не нужны** для `car-service-platform` (другие проекты, эксперименты, дубли plugin + stdio).
- Ссылка на этот файл и на `docs/dev/agents-and-mcp.md` (рекомендуемый минимальный набор).

Шаблон текста (адаптировать под клиент пользователя):

```text
MCP hygiene: лишние подключённые MCP увеличивают контекст и шум. Отключите в настройках те серверы,
которые не нужны для этой задачи/репозитория (см. docs/dev/mcp-deduplication.md). Рекомендуемый минимум — docs/dev/agents-and-mcp.md.
```

В отчёте агента: поле **`MCP hygiene`** (см. корневой `AGENTS.md`).

## Следующие сессии: не подключать лишнее автоматически

**Репозиторий не может** отключить чужие глобальные MCP за пользователя: это делает **клиент** (Cursor / Claude Code / Codex).

Что реально работает:

| Клиент | Как ограничить на будущее |
|--------|---------------------------|
| **Codex** | В **`~/.codex/config.toml`** оставьте только нужные `[mcp_servers.*]` **или** задайте `enabled = false` для лишних. Для **только этого репозитория** Codex подмешивает проектный слой: файл **`.codex/config.toml` в корне репо** (в этом проекте есть шаблон с примером) — при **trusted** проекте можно явно отключать серверы по имени, совпадающему с глобальным. |
| **Cursor** | В UI MCP отключите ненужные серверы **глобально** или используйте **workspace-/project-настройки** текущей версии Cursor (см. актуальную документацию Cursor по MCP). Изменения в user config сохраняются до следующего включения. |
| **Claude Code** | Отключение в UI / в user `settings.json`; дубли — убрать из project-local секции `~/.claude.json` для пути репо. |

Итог: **автоматически «не поднимать в следующий раз»** возможно только там, где клиент хранит ваш выбор (отключённые серверы, `enabled = false`, узкий user config). Скрипты этого репо **не удаляют** чужие глобальные MCP и **не меняют** плагины ECC — только не добавляют лишний stdio-профиль по умолчанию.

## Чеклист агента

1. Перед `install-user.mjs`: открыть список MCP (как у пользователя) — есть ли уже context7 / playwright / github / … от плагина или User?
2. Если да — использовать **default** профиль (пустой), не `--profile standalone`.
3. Если пользователь просит убрать дубли — удалить **project-local** дубликаты, сохранить plugin/global.
4. В ответе указать: `MCP dedupe: …` (что оставили и почему).
5. Вывести **MCP hygiene** пользователю (см. выше) и заполнить поле **`MCP hygiene`** в отчёте.
